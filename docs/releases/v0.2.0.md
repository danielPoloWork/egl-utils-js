# egl-utils-js v0.2.0

Milestone 9 of the second capability wave: three new tree-shakeable entry points and four
additions to the existing surfaces — string shaping, strict IPv4/CIDR handling, the query
primitives behind a data table, duration and error formatting, a per-tab correlation id,
and a REST resource factory.

```bash
npm install egl-utils-js
```

Additive throughout: nothing in the v0.1.0 surface changed behaviour, and the root entry
still carries zero runtime dependencies.

## What's new

| Entry | Added |
|---|---|
| `egl-utils-js` | `formatDuration`, `normalizeError`, `createResource` |
| `egl-utils-js/text` *(new)* | `truncate`, `wrapText`, `fixedWidth` |
| `egl-utils-js/net` *(new)* | `isIpv4`, `parseIpv4`, `formatIpv4`, `ipv4ToKey`, `ipv4FromKey`, `subnetMaskFromPrefix` |
| `egl-utils-js/table` *(new)* | `compileFilter`, `comparator`, `paginate` |
| `egl-utils-js/storage` | `pageSessionId` |

**A filter grammar that cannot throw, and cannot backtrack.** `compileFilter` turns a
user-typed expression — substring, `=`, `!=`, `^prefix`, `suffix$`, numeric comparisons,
and `null`/`empty`/`blank` sentinels — into a predicate. It is *total*: every string
compiles, including a half-typed one, so a filter box can compile on every keystroke
without a `try`/`catch`. No `RegExp` is ever constructed from user input, so the ReDoS
shape that filter boxes usually invite is absent by construction. Applications add their
own operators through `options.operators` instead of forking the grammar.

**Sorting that is actually a total order.** `comparator` pins blanks to one end
*regardless of direction*, orders mixed types by type before value (per-pair type
detection, the intuitive approach, is intransitive — and an intransitive comparator is
undefined behaviour for `Array.prototype.sort`, not merely an odd order), and collates
text through `Intl.Collator` so `'item 9'` precedes `'item 10'`. Locale is opt-in for
reading numbers, so results never depend on the machine's regional settings.

**Strict IPv4 parsing, for a security reason.** Four decimal octets, no leading zeros,
none of the legacy `inet_aton` shorthand, octal, hex, or bare-integer forms. Different
components disagree about what `010.0.0.1` means, and a validator disagreeing with a
resolver is the mechanism behind allowlist-bypass and SSRF bugs. `isIpv4` and `parseIpv4`
accept exactly the same language, asserted as a property. The companion key codec makes
address order equal string order, so a list of addresses sorts correctly in a database
column and octet-aligned network membership is a `startsWith`.

**Errors you can log without losing.** `normalizeError` maps anything a `catch` block can
receive — an `Error`, a string, a response object, `null`, a symbol, a value whose
`message` getter throws — to one record shape, never throwing, with the original carried
through by identity. The idiom is one line: log the record, rethrow the original.

**A REST collection in one line.** `createResource(client, 'users')` returns the six
methods every collection otherwise grows by hand. The client is a *parameter*, never an
import: anything with `get`/`post`/`put`/`patch`/`delete` works, so the factory costs
505 B rather than inheriting the 1304 B `httpClient` facade, and testing it needs neither
a network nor a mocking framework. Ids are encoded as exactly one path segment, so an id
containing `/` or `..` can never widen the path it was meant to address.

## Note for `/storage` consumers

A full-entry import of `egl-utils-js/storage` grows from 1706 B to **2027 B**, because
`pageSessionId` reuses `uuid` rather than reimplementing entropy handling. Importing only
the three original wrappers now costs **1698 B — slightly less than before** — so the cost
falls solely on users of the new function, and that scenario is pinned as its own
permanent budget row. The NFR-01 `/storage` clause is amended from 2 kB to 2.1 kB, with
the measurements recorded in
[ADR-0024](https://github.com/danielPoloWork/egl-utils-js/blob/main/docs/adr/0024-page-session-id-scope-and-budget.md).

## Supported platforms

Node.js >= 18 · Safari >= 15.4 · last two versions of Chrome, Firefox, and Edge ·
TypeScript >= 5.0. Published as dual ESM/CJS with types generated per format. The three
new entries are Node-safe and touch no platform global beyond ECMA-402 `Intl`.

## Known limitations

- `Array.prototype.sort` relocates `undefined` elements to the end of the array itself,
  without consulting any comparator — so `comparator({ emptiesLast: false })` pins `null`
  and `''` first, but a literal `undefined` still lands last when sorting in place. No
  implementation can change this; normalize to `null` when it matters.
- The filter grammar has no boolean composition (`AND`/`OR`/parentheses). Per-column
  filters are combined by the caller; adding composition later would change what a space
  in an expression means, so it is a deliberate future decision rather than an omission.
- `createResource` does no caching, response normalization, or optimistic updates. A
  Repository mediates access; a store manages state.
- Pre-1.0: the surface is complete and gated but not yet frozen under a stability
  contract. Breaking changes before 1.0.0 arrive as `MINOR` bumps.
