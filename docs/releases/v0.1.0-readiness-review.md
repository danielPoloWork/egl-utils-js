## 1. What this review found

### 1.1 A real portability defect — `AbortSignal.timeout` vs the Safari 15.4 floor (FIXED here)

**NFR-07 declares `Safari >= 15.4` supported. `AbortSignal.timeout()` first shipped in Safari 16.0.**
`async.js` called it unconditionally, so on Safari 15.4–15.6:

- `timeout()` threw `TypeError: AbortSignal.timeout is not a function`;
- `httpClient()` threw the same, because ADR-0007 has it compose `timeout()`.

That is **two of the 25 public functions non-functional on a browser the spec promises** — a false portability claim, not a cosmetic gap. It survived six milestones because nothing in the test matrix runs a browser that old: Playwright's WebKit is far newer than Safari 15.4 (see §3.7).

**Fixed** with an internal `timeoutSignalFor(ms)` fallback, deliberately shaped like the existing `anySignal` helper — which exists for the same class of reason (`AbortSignal.any` is missing on the Node 18 floor, ADR-0004). The fallback aborts with a `TimeoutError` `DOMException`, mirroring the platform's own reason, so `timeout`'s error mapping and any downstream inspection (e.g. `httpClient`'s fetch) are unchanged.

Verified both directions: the three new tests fail with exactly `AbortSignal.timeout is not a function` when the fallback is removed, and pass with it. Coverage held at 100% by **deleting** a dead `typeof DOMException` guard rather than mock-covering it — the precedent this project set in M2.4.

> **Alternative the owner may prefer:** raise NFR-07's floor to Safari 16.0 and drop the fallback. That narrows the supported matrix, which is a product decision, not an implementation one — so the fallback was chosen to *keep the stated promise* rather than quietly shrink it.

### 1.3 The release is a two-PR sequence, by construction

Non-obvious and worth stating before someone hits it: the consistency lint asserts that *the newest `docs/changelog/vX.Y.Z.md` equals the version in `version.js`*. So the prose artifacts **cannot** be written before the bump lands — creating `v0.1.0.md` while `version.js` still says `0.0.0` fails the gate.

Correct order:

1. merge this PR → Version PR opens proposing `0.1.0` (its `changeset:version` step also propagates the version into `version.js` and the README badge);
2. add `docs/changelog/v0/v0.1.0.md` and `docs/releases/v0.1.0.md`, and roll `CHANGELOG.md`, **on that Version PR** (or a follow-up before tagging);
3. merge it; 4. tag; 5. publish the GitHub Release; 6. dispatch **publish**.

The Version PR passes CI without the prose (the lint skips the check when no changelog files exist at all), so step 2 can also follow — but it must precede tagging.

### 3.6 TypeScript 5.0 — verified during this review

Previously only *claimed*: the toolchain builds with TS 5.9, and `arethetypeswrong` validates module **resolution**, not compiler-version compatibility. Verified here by installing **`typescript@5.0.4`** in a clean project, linking the built `dist/`, and compiling a realistic consumer under `module: node16`, `moduleResolution: node16`, `strict: true`, `types: []` — exercising generics (`EventEmitter<EventMap>`, `groupBy` → `Map<string, number[]>`, `retry` → `string`, `measure` → `{result, ms}`) across all four entry points.

**Result: 0 errors, exit 0.** (A first attempt reported errors from a hoisted `@types/node`, unrelated to this package; isolating with `types: []` removed that contamination.)

### 3.7 Browsers — what is and is not verified

The Playwright suite (60 tests × Chromium/Firefox/WebKit) is real evidence, but it does **not** cover the clause as written:

- **"last 2 evergreen versions"** — Playwright bundles *one* pinned build per engine. Only that build is exercised.
- **"Safari ≥ 15.4"** — Playwright's WebKit is Safari's *engine*, not Safari, and its build is far newer than 15.4. §1.1 is the concrete consequence: a Safari-15.4-only defect existed and no browser job could have caught it.

Not a blocker, but the claim should be read as *"three current engines verified"*, and residual Safari-15.4 risk assessed by API-support review rather than by test evidence. A `browserslist`/API-floor lint would close this properly — filed below.

## 4. Standing divergences requiring an owner ruling

1. **NFR-01 per-function budget vs `httpClient` (1315 B, 31% over).** The overage *is* the composed `timeout` + `HttpError` that ADR-0007 deliberately reuses (verified: `{httpClient}` 1251 B, `{httpClient, timeout}` 1252 B — one byte). Fitting 1 kB means inlining a second timeout implementation. Recorded in ADR-0015 and inline on NFR-01; budget currently 1.35 kB, labelled as an exception in CI output. §1.1's fix added 64 B to it, which the gate correctly refused until the budget was raised deliberately (ADR-0015 addendum). **Decide:** accept permanently / amend NFR-01 to exempt composing facades / require redesign.
2. **`GHSA-mh99-v99m-4gvg`** (`brace-expansion` DoS) excepted per-GHSA in `pnpm.auditConfig`. Dev-only, unreachable in this threat model, never shipped, and unfixable here (forcing the patched version breaks `minimatch@9` — demonstrated in ADR-0016). **Decide:** accept until eslint/vitest move to `minimatch@10`.
