# egl-utils-js v1.2.0

**A table stops being a rendering of your data and starts being a component you can hand a
user.**

```bash
npm install egl-utils-js@1.2.0
```

```js
import { bsTable } from 'egl-utils-js/bootstrap';

const table = bsTable(host, {
  columns: [
    { key: 'host', label: 'Host', sortable: true, minWidth: 120 },
    { key: 'ip', label: 'Address', sortable: true },
    { key: 'seen', label: 'Last seen', type: 'date' },
  ],
  data: rows,
  rowKey: 'id',
  pageSize: 25,
  responsive: true,
  selection: true, // a checkbox column with a real indeterminate header
  sticky: { maxHeight: '420px' }, // the header stays while the body scrolls
  resize: true, // drag or arrow-key a column's width
  reorder: true, // drag or arrow-key a column's position
  controls: { filterRow: true, search: true, pagination: true },
});
```

Milestone 19 delivers spec 06 (F88–F100). **Purely additive**: v1.0.0 froze a 113-export
surface, this release adds ten exports and six `bsTable` options, and changes none of the 113.
No `EGL_*` code is renamed, and the `exports` map is untouched — if you use this package today,
nothing you wrote stops working.

## Data can come from somewhere else

**`remotePipeline`** is a table pipeline whose rows come from a server, speaking the same
command vocabulary as `tablePipeline` — so moving a table from local to remote data changes
where the rows come from and nothing the calling code has to relearn. It is a **sibling, not a
wrapper**: a binder that fed the server's already-filtered page into a pipeline that filters
again would have reused more code and shipped a silent double-derivation.

A superseded load is **aborted**, not merely ignored, and its result is discarded even if it
arrives first. An identical query does not re-issue — `refresh()` asks again on purpose. A
failed load **leaves the previous rows in place** with the error beside them, because a table
that empties itself on a network blip has thrown away the only thing the user still had.

**`tableStateToParams` / `tableStateFromParams`** convert a table's state and a query string
both ways, exactly and purely — so a server render can restore the state from the request and
derive the right page before any script runs. Parameters the state does not own are preserved,
defaults are omitted so a table at rest has a clean URL, and nothing throws on input: `page=abc`
is page 1, and one malformed sort entry is dropped while the ones around it survive.
**`bindTableHistory`** keeps a live pipeline and the address bar in step, restoring in a single
transaction — four restored commands firing four `change` events would land you back on page 1.

## The user can change what they see

- **Row selection**, keyed by row key rather than by index or identity, so a selection survives
  a re-sort and a server round-trip. Single or multiple, an indeterminate header checkbox, and
  select-all that means **this page and only this page** — never "everything matching the
  filter", which has shipped as a data-loss bug in more than one table.
- **CSV export and clipboard.** RFC 4180, client-side, zero-dependency — and **formula injection
  neutralised by default**, because a CSV opened in a spreadsheet is a code-execution surface
  and the data in an export is whatever your users typed. Documented and defeatable. Clipboard
  failures are typed, so "nothing happened" is distinguishable from "it worked".
- **A sticky header** that is five CSS declarations and nothing else: no scroll listener, no
  `requestAnimationFrame`, no layout measured in JavaScript.
- **Column resize**, by drag *and* by arrow key, with widths you can read and restore, minimum
  widths enforced, and **no row ever re-rendered** — widths live on a `<colgroup>`.
- **Column reorder**, by drag *and* by arrow key, over an order that is yours: `getColumnOrder()`
  / `setColumnOrder()` mean you can build your own control, or none at all, and persist a layout
  without touching the DOM.

Every pointer affordance has a keyboard path through the **same control** — not a second one
bolted beside it — and none of the five reaches the pipeline that decides which rows you are
looking at.

## Fixed

- A column keyed `__proto__` was filtered for real but reported by `view()` as unfiltered, so
  every consumer of `view().filters` saw a table that disagreed with itself
  ([BUG-0004](https://github.com/danielPoloWork/egl-utils-js/blob/main/docs/bugs/2026/08/BUG-0004-view-filters-lose-a-proto-column.md)).
- A table with both a selection column and a filter row drew every filter input under its
  neighbour, with the last column appearing to have none — silently, because the wiring stayed
  correct
  ([BUG-0005](https://github.com/danielPoloWork/egl-utils-js/blob/main/docs/bugs/2026/08/BUG-0005-filter-row-misaligned-under-a-selection-column.md)).

Neither had reached a released version; both were found and fixed inside this wave.

## Compatibility

Unchanged: **Node ≥ 22**, Safari ≥ 16.4, the last two evergreen Chromium/Firefox/Edge. Zero
runtime dependencies. `bootstrap` and `dompurify` remain optional peers, resolved at first use
and failing typed when absent. The `exports` map is byte-identical to v1.1.0, and both
no-bundler routes — deep ESM and the single-file artifact — carry the new surface.

Seven platform APIs are newly reached and each is declared explicitly: the History API for URL
state, the async Clipboard API for copy, and Pointer Events with pointer capture for resize and
reorder. All are inside the supported floor.

## Verified

2 820 tests at 100% line coverage, plus property suites where examples are the wrong tool: the
async contract is proved against **randomised command/response interleavings** — out-of-order
arrival, abort-then-arrive, coalescing — rather than against the races someone thought of.
Selecting all on a 10 000-row source and reading a 10 000-key selection are each under 10 ms,
and selection costs O(selected) memory rather than O(source).

Every pointer feature is asserted in a **real engine** on Chromium, Firefox and WebKit: that the
sticky header holds the container's top edge while row one scrolls above it, that a drag moves a
column boundary and the width survives the pointer leaving the table, and that a reorder drag
swaps the columns under the cursor with the filter row travelling along.
