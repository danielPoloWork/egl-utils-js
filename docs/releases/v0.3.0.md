# egl-utils-js v0.3.0

Milestone 10, and the completion of the second capability wave: one new tree-shakeable
entry point, `egl-utils-js/logging` — a structured logger whose destination, line shape,
clock, and correlation id are all yours to supply.

```bash
npm install egl-utils-js
```

Purely additive: nothing in the v0.2.0 surface changed behaviour, and the root entry still
carries zero runtime dependencies. With this release **every requirement of the second
specification (F26–F41) is delivered.**

## What's new

| Entry | Added |
|---|---|
| `egl-utils-js/logging` *(new)* | `logger`, `formatLogLine`, `formatTimestamp`, `LOG_LEVELS` |

```js
import { logger } from 'egl-utils-js/logging';

const log = logger({ level: 'debug', name: 'checkout' });
log.info('order placed', { id: 42 });
// 2026-08-06 09:30:12.007 INFO  --- [            checkout] order placed
log.trace('not emitted — below the threshold');
log.child('db').warn('slow query'); // named 'checkout.db'
```

**One threshold, not a flag per severity.** Eleven booleans admit 2048 states, most of them
nonsense ("errors off, trace on"), none of them orderable, and none able to answer "is
debug enabled?". `level` is the single switch, `'silent'` turns everything off, and a call
below the floor returns before the clock is read, the id resolved, or a record allocated —
so leaving `log.debug(expensiveSummary())` in production code costs the argument, not the
machinery.

**The sink chooses the destination; the formatter chooses the shape; the sink receives
both.** A sink is `(record, format) => void`. A text sink calls the formatter; a structured
transport ignores it and never pays to build a string it would throw away:

```js
logger({ sink: (record) => queue.push(JSON.stringify(record)) }); // no line is built
logger({ sink: (record, format) => appendFile(format(record) + '\n') }); // text
```

**Context is a string you wrote.** `child('db')` names a child logger `'parent.db'`. The
tempting alternative — deriving names by reflection from `this` and function references —
reads beautifully at the call site and then breaks under minification: silently, in
production only, and in every log line at once.

**Logging never throws into your code.** A logger is called from `catch` blocks, so the
worst failure mode is one that replaces the error you were recording. A dead sink, a
throwing clock, a throwing id function, a hostile `toString`, or a throwing formatter costs
that single record and is reported once through `console.error`; if `console.error` is
itself missing or throwing, the failure is dropped rather than escalated. The call that
logged always returns normally.

```js
logger({
  sink: () => {
    throw new Error('transport down');
  },
}).info('this still returns');
```

**One record renders as exactly one line — for every input.** CR and LF are collapsed to a
single space in the message *and* in the name and id columns. The id matters most: it comes
from a function you inject, so it is no more trusted than the message. Without that, text
arriving from a user could forge a second log entry — a fake `ERROR`, a bogus audit line,
or a value that shifts every downstream parser's columns. A property test asserts the
guarantee over arbitrary strings, and the browser suite re-checks it in Chromium, Firefox,
and WebKit.

**Testing it needs no `console` spy.** Freeze the clock, capture the records:

```js
const lines = [];
const log = logger({ now: () => 0, sink: (r, format) => lines.push(format(r)) });
```

## Sizes (min+brotli)

| Import | Size |
|---|---|
| `egl-utils-js/logging` (whole entry) | 1390 B |
| `{ formatLogLine }` | 876 B |
| `{ formatTimestamp }` | 301 B |
| `{ LOG_LEVELS }` | **60 B** |
| `{ logger }` | 1361 B — a documented budget exception |

`logger` exceeds the 1 kB per-function clause because importing the factory imports the
subsystem it composes: the default formatter, the default sink, and the fixed-width column
primitive. The exception is named and measured in the size budget rather than waived, the
same treatment `httpClient` received. The 60 B `LOG_LEVELS` figure is the informative one —
it shows composition is what costs, not the entry.

## Also in this release

- **The supply-chain gate now runs with zero audit exceptions.** A new high advisory in a
  dev-only dependency path
  ([GHSA-rgw5-rvv9-x895](https://github.com/advisories/GHSA-rgw5-rvv9-x895)) is fixed by a
  range-scoped override rather than suppressed, which in turn made a previously documented
  exception obsolete — so it was retired instead of extended. **No published bytes change:**
  development dependencies never reach a consumer.
- The threat model gains a **Log records** trust boundary with a full STRIDE pass, including
  an explicit **no redaction** claim: the library adds no destination of its own, and
  deciding what may be logged stays with the caller.

## Compatibility

- Node.js ≥ 18; last two Chromium/Firefox/Edge versions; Safari ≥ 15.4.
- ESM and CommonJS, with types generated per format.
- Zero runtime dependencies. The new entry touches no platform API beyond `console`.
- No breaking change: every v0.1.0 and v0.2.0 export keeps its behaviour.
