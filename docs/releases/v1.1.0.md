# egl-utils-js v1.1.0

**The plain HTML page becomes a first-class consumer.**

```bash
npm install egl-utils-js
```

…or don't. That is the point of this release:

```html
<script src="https://cdn.jsdelivr.net/npm/egl-utils-js@1.1.0"></script>
<script>
  const rows = egl.table.paginate(data, { page: 1, pageSize: 20 });
  document.body.append(egl.bootstrap.bsBadge(`${rows.total} results`));
</script>
```

Every wave until now shipped for the npm consumer: install, import, let a bundler resolve the
graph. Milestone 18 closes the gap for the page that has no `package.json`, no bundler and no
Node — an intranet tool, a server-rendered app with a `<script>` tag, a reproduction on CodePen.
The library now works by being **loaded**, not by being **built**.

**Purely additive.** The `exports` map is byte-for-byte identical, a bundler consumer re-bundles
to exactly the same graph, `sideEffects: false` still holds and runtime dependencies are still
zero. If you use this package through a bundler, this release changes nothing for you.

## Two routes, no build step

**Deep ESM, one entry at a time** — load only what you use. No import map is needed: every
entry's internal imports are relative paths to its own chunks, never a bare specifier.

```html
<script type="module">
  import { retry } from 'https://cdn.jsdelivr.net/npm/egl-utils-js@1.1.0/dist/esm/index.js';
  import { truncate } from 'https://cdn.jsdelivr.net/npm/egl-utils-js@1.1.0/dist/esm/text.js';
</script>
```

**The global artifact** — the whole public surface in one file, read as the global `egl`, which
is what the bare CDN URL above resolves to. The root entry's exports sit at the top level
(`egl.retry`, `egl.VERSION`); each subpath is a sub-namespace named after its `exports` path
(`egl.text`, `egl.table`, `egl.bootstrap`, …). Nothing is renamed, and loading it has no effect
beyond defining `egl`.

**Pin one version for every `egl-utils-js` URL on a page.** Entries share content-hashed chunks
*within* a version, not across one, so mixing versions double-loads shared code — and can leave
two copies of the same class in one page.

## What each route costs

Measured, and gated in CI so the figures cannot drift. This is what a browser actually
transfers — every file in the entry's chunk graph, each compressed as its own response:

| Route | Requests | Transferred |
|---|---:|---:|
| `/errors` | 2 | 1.07 kB |
| `/net` | 2 | 1.34 kB |
| `/text` | 3 | 1.67 kB |
| `/sanitize` | 3 | 2.91 kB |
| `/logging` | 3 | 3.06 kB |
| `/storage` | 4 | 4.25 kB |
| `/table` | 4 | 6.75 kB |
| `/dom` | 7 | 10.85 kB |
| root | 7 | 13.45 kB |
| `/bootstrap` | 7 | 31.28 kB |
| **the artifact** | **1** | **31.51 kB** |

**If you need `/bootstrap`, take the artifact** — the whole surface in one request for within 1%
of what that one entry costs in seven. The deep-ESM route earns its keep at the other end of the
table.

These numbers are larger than the per-function budgets quoted in the README, and that is not a
contradiction: those measure what a *bundler* ships after tree-shaking, while a static page
downloads whole files. Both are real; they belong to different consumers.

## The optional peers

Unchanged, and unbundled on both routes. Neither `bootstrap` nor `dompurify` is packed into the
artifact, so a page that already loads one does not end up with two copies. Both are resolved at
first use, so a page that loads Bootstrap's own bundle needs no configuration at all:

```html
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5/dist/js/bootstrap.bundle.min.js"></script>
```

A missing peer is still the typed `EGL_PEER_MISSING`, naming the package, **at the call that
needed it** — never a failure at load.

## Compatibility

| | |
|---|---|
| **Node.js** | **>= 22** (CI matrix: 22 / 24 / 26) |
| **Browsers** | **Safari >= 16.4**; last 2 Chrome, Firefox, Edge |
| **Module formats** | ESM and CJS via the `exports` map, plus the new IIFE artifact for `<script src>` |
| **TypeScript** | >= 5.0, resolving types through the exports map |
| **Runtime dependencies** | **zero** |
| **Optional peers** | `bootstrap@^5`, `dompurify@^3.4.13` — both looked up, never imported |

The 1.x stability promise is unchanged and stated in
[`README.md`](https://github.com/danielPoloWork/egl-utils-js#stability-promise): every named
export, every `EGL_*` code and every `exports`-map path is MAJOR-protected, as is the runtime
floor. This release only adds — including two new advertised paths, `unpkg` and `jsdelivr`, which
join that promise from today.

No new platform APIs are used, and the browserslist floor does not move.

## Verified

The no-bundler routes are not documentation-only claims. CI loads the package **exactly as the
README says to**, on **three engines** (Chromium, Firefox, WebKit), from a static file server
with no bundler in the loop — asserting per route that the entry is reachable, `VERSION` matches
`package.json`, a builder renders and escapes, a peer-backed call works once its peer arrives
from a script tag, and peer absence is typed rather than fatal at load.

Three new packaging gates run on every build: the artifact's surface, version lockstep and
single-global guarantee, checked against the built file; every advertised path present in the
**packed tarball**; and the transferred bytes above.
