# egl-utils-js v0.9.0

**The Bootstrap 5 catalogue is complete: all 24 components.** With `bsTable`, `bsIcon` and
`bsLoadingOverlay` alongside them, `egl-utils-js/bootstrap` is 29 named exports on one
opt-in entry — each individually tree-shakeable, so adopting one costs you nothing of the
rest.

```bash
npm install egl-utils-js
```

This release adds the half that needs Bootstrap's own JavaScript, and the interesting part
is that the entry still **imports it nowhere**. A wrapper resolves the optional `bootstrap`
peer the first time you *use* one — the injected `{ bootstrap }` option first, then the
`window.bootstrap` a CDN bundle defines. So the element builders keep working with no peer
installed, importing the entry can never fail for someone who only wanted a badge, and a
bundle that loads late still works.

Additive, with one behaviour correction and one defect fix noted below. The root entry is
untouched; the package still declares **zero runtime dependencies**.

### The markup builds itself, and the ARIA comes with it

```js
import { bsAccordion, bsTabs, bsNavbar } from 'egl-utils-js/bootstrap';

const faq = bsAccordion(container, {
  items: [
    { header: 'What is it?', body: 'A toolkit.', open: true },
    { header: 'Why build the markup?', body: someNode },
  ],
});
faq.open(1);
```

Navigation components express their accessibility through **ids** — `aria-controls`,
`aria-labelledby`, `data-bs-target` — and ids are what hand-written templates get wrong: a
stale one is invisible, and a duplicate makes every relationship resolve to the same
element while *looking* correct. So each is minted against the live document and against
the batch being built, and cannot collide with either. Given no items, each manager adopts
the markup already on the page instead, and `destroy()` removes only what it built.

### One sanitizer, and it is yours

```js
import { bsPopover } from 'egl-utils-js/bootstrap';
import { sanitizeHtml } from 'egl-utils-js/sanitize';

// A plain string is text: no sanitizer runs on either side.
bsPopover(button, { title: 'Draft saved', content: 'Kept locally until you publish.' });

// Markup needs the explicit pair — and your sanitizer is the only one that runs.
bsPopover(button, {
  title: '<b>Draft saved</b>',
  content: '<em>Kept locally.</em>',
  html: true,
  sanitize: sanitizeHtml,
});
```

Tooltips and popovers are the only pair that hands content to Bootstrap to render, and
Bootstrap ships its own sanitizer, on by default. Two passes over one value is not twice
the safety — it is a boundary with no owner, and the visible effect is the profile you
chose being narrowed by one you never saw. So yours runs first, and Bootstrap's is switched
off for that content.

### A missing peer tells you which one

```js
try {
  tooltip.show();
} catch (error) {
  error.code; // 'EGL_PEER_MISSING'
  error.peer; // '@popperjs/core' — the bootstrap install was already fine
}
```

Bootstrap positions tooltips and popovers with Popper, which `bootstrap.bundle` carries and
the plain build does not. Rather than a generic "peer missing" that sends you to re-check
the package that was working, the failure names the one to install.

### Teardown is a first-class API

Every wrapper and manager returns `destroy()`, and every one honours an `AbortSignal`.
Where a component is still open, `destroy()` closes it **first** and disposes once it has
actually gone — disposing an open modal or offcanvas is what strands Bootstrap's backdrop
and leaves the page scroll-locked.

## Changed

`bsToast` now builds in its container's own document rather than the ambient one, matching
every other container-taking manager. For a container inside an iframe the previous
behaviour built nodes in the top document. Corrected before any release shipped it.

## Fixed

Builders that own a listener now work against a document from another realm — an iframe, a
popup, or a `new JSDOM()` document under Node. Each created its `AbortController` in the
library's realm and handed the signal to `addEventListener` on a node from another, which
the DOM refuses; so the `{ document }` option worked for builders that rendered and failed
for builders that also listened. Affects `inlineAlert`, `delegate`, `autoGrow` and
`bindTableControls` on `egl-utils-js/dom`, and `bsAlert`, `bsPagination`,
`bsListGroup({ onSelect })` and `bsTable`'s row activation on `egl-utils-js/bootstrap`
([BUG-0003](https://github.com/danielPoloWork/egl-utils-js/blob/main/docs/bugs/2026/08/BUG-0003-cross-realm-abort-signal-in-composites.md)).

## Verification

2213 tests on Node 18/20/22 at 100% line coverage, plus 94 real-engine scenarios per
browser in Chromium, Firefox and WebKit — driving the actual Bootstrap bundle, because the
one claim a fake DOM cannot settle is that *Bootstrap's own plugins accept the markup this
library generates*. Packaging gates unchanged: `publint`, `arethetypeswrong`, `size-limit`,
`agadoo`, and the zero-runtime-dependency check.

One budget number worth publishing: the entry measures **19163 B** against a **25 kB**
ceiling set before any of this wave existed — four milestones and 29 exports later, it has
never been amended.
