# egl-utils-js v1.3.0

**The layer above a component: behaviour that outlives any one of them.**

```bash
npm install egl-utils-js@1.3.0
```

```js
import { createDialogs, createToasts, createTheme } from 'egl-utils-js/ui';

const dialogs = createDialogs();
if (await dialogs.confirm('Delete this host?')) await api.delete(host.id);
// Escape, the backdrop, the close control and Cancel all RESOLVE false.
// A rejection means the question could not be asked — not that the answer was no.

const toasts = createToasts({ maxVisible: 3 });
await toasts.promise(api.save(form), {
  pending: 'Saving…',
  success: (saved) => `Saved as ${saved.name}`,
  error: (err) => `Could not save: ${err.message}`,
}); // one toast, transitioned in place — and your own promise back, untouched

createTheme().control({ mountTo: header }); // data-bs-theme, no flash, named for where it goes
```

Milestone 20 delivers spec 07 (F101–F111). **Purely additive**: v1.2.0's 123 exports are
untouched — this release adds **ten exports and one new entry**, renames no `EGL_*` code, and
leaves the existing `exports` map paths byte-identical. If you use this package today, nothing
you wrote stops working.

## A dialog is a question, and a question has an answer

`createDialogs` puts a promise around the F70 modal wrapper instead of reimplementing it, and
settles the thing every hand-rolled version gets wrong differently: **a dismissal is an answer,
not an error.** Escape, the backdrop, the close control and Cancel all resolve — `false` for a
confirm, `null` for a prompt, distinguishable from the empty string a user may actually have
typed. A rejection means the dialog could not be *asked*, and keeps the two codes it already
had: `EGL_DOM_CONTRACT` with no document, `EGL_PEER_MISSING` with no Bootstrap.

Exactly one settlement survives any race, because the answer is recorded before anything starts
closing. Focus is trapped while the dialog is open and restored to whatever opened it — and the
dialog places focus itself, because on WebKit leaving that to Bootstrap let the first Tab press
escape the dialog. `destroy()` **settles** every dialog still open rather than abandoning the
promises.

## A notification is a stream, not an event

`createToasts` adds the one thing `bsToast` has no opinion about: a policy. A visible cap with a
queue promoted in arrival order, so a loop of forty notifications shows three at a time instead
of burying the page it is reporting on. Adding again with an **id** the manager still holds
updates that toast in place; an **identical** message is dropped rather than shown twice, and
"identical" is defined rather than left to the reader — same `variant`, `title` and `message`,
and only when both strings, because node content can be compared only by reference and a rule
that silently never fires is worse than an honest exemption.

`promise()` tells one story with one toast. It returns **your** promise, so the settlement
passes through untouched and an unhandled rejection stays yours.

## A preference is state, and state has a lifetime

`createTheme` drives Bootstrap 5.3's own `data-bs-theme` and nothing beside it — the attribute
name is deliberately not an option, because a configurable one is how a second theming
mechanism starts. **`'auto'` is the absence of a stored choice rather than a third state**, so
"no choice yet" and "follow the system" cannot drift apart; and an expressed choice *stops*
system tracking until it is withdrawn, which is why a site that remembered your preference at
6 pm still has it at 7.

`themeSnippet()` returns the synchronous `<head>` script that applies a persisted theme
**before first paint** — emitted rather than documented, because a README snippet shares the
storage key and the attribute with the manager only by coincidence, and the suite asserts the
two agree by running the string.

`createBreakpoints` is Bootstrap's four SCSS mixins with the meanings **its source** gives them,
not the ones the names suggest: `down('md')` is *narrower than md*, the Bootstrap 5 change
people trip over. It opens five `min-width` queries rather than eleven, and the `0.02px`
subtraction a hand-rolled version mistypes appears nowhere in this library.

## The primitives that existed exactly once

`focusTrap`, `saveFocus`, `liveRegion` and `reducedMotion` land on `egl-utils-js/dom`, needing
no component library at all. The trap is **scoped to Tab deliberately** — it corrects the edge
the key is about to leave through and leaves everything between to the browser's own tab order,
with no document-level `focusin` guard to fight focus moved by assistive technology. A root with
nothing focusable **holds focus itself** rather than losing it to `<body>`, the case that
otherwise turns a trap into a lock.

`liveRegion` closes a gap [ADR-0069](https://github.com/danielPoloWork/egl-utils-js/blob/main/docs/adr/0069-an-order-is-a-permutation-and-the-ceiling-held.md)
named rather than hid: a column moved by v1.2.0's keyboard path was announced to nobody.

## Why a new entry

`egl-utils-js/ui` exists because [ADR-0041](https://github.com/danielPoloWork/egl-utils-js/blob/main/docs/adr/0041-a-peer-looked-up-not-imported.md)
sized `/bootstrap`'s 25 kB clause for the finished catalogue, and 482 B of it were left — while
the modal and toast wrappers these managers compose measure 1 266 B and 2 473 B on their own.
The wave did not fit, and no amount of care would have made it fit.

The boundary between the two entries is testable rather than aesthetic: `/bootstrap` **builds**
components, `/ui` **orchestrates** them, and a symbol belongs on `/ui` if it would still make
sense with a different component library underneath. A toast *queue* would; `bsBadge` would not.

## Compatibility

Unchanged: **Node ≥ 22**, Safari ≥ 16.4, the last two evergreen Chromium/Firefox/Edge. Zero
runtime dependencies. `bootstrap` and `dompurify` remain optional peers, resolved at first use
and failing typed when absent. Existing `exports` paths are byte-identical to v1.2.0; `./ui` is
added beside them, and both no-bundler routes — deep ESM and the single-file artifact — carry it.

Three platform APIs are newly reached and each is declared explicitly: `matchMedia`,
`MediaQueryList.matches` and `MediaQueryList.change`. The last is the one worth confirming rather
than assuming — Safari 14 — which is what makes the deprecated `addListener` unnecessary at a
16.4 floor. All are inside the supported floor.

The single-file artifact measures 44 390 B, and NFR-22's ceiling was **re-derived** to 62 kB by
the same sum-of-measured-entry-figures method spec 05 defined — six times across this wave, once
per item that moved an input. A clause nobody recomputes is a number rather than a bound.

## Verified

**3 078 tests at 100% line coverage**, plus property suites where examples are the wrong
instrument: the toast queue's cap and admission rules are proved against randomised arrival
sequences rather than the sequences someone thought of, and the dialogs' exactly-one-settlement
guarantee is asserted by *counting* settlements under raced dismissals, not by observing the
value.

Every claim only an engine can settle is asserted on Chromium, Firefox and WebKit: that focus
returns to the element that opened a dialog, that a persisted theme is already on the attribute
at first paint, that the real `MediaQueryList` is wired, and that an announcement leaves focus
unmoved.

The suite that proves all of that also got fixed. It had been failing 3–4 tests per full run, a
different set each time. v1.3.0's last item measured the diagnosis it had been filed with — that
the test static server was the bottleneck — and **disproved it**: the cause was Playwright's
default worker count, half the machine's cores, a rule that scales the wrong way. Bounded, the
suite runs 160/160 and faster.
