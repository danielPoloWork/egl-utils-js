# egl-utils-js v0.4.0

A new tree-shakeable entry point, **`egl-utils-js/dom`**: ten browser helpers for the work
applications actually spend their utility budget on — binding elements at startup, delegating
events, setting form values, injecting HTML fragments, growing a textarea, and adding a query
parameter to a URL that may already have one.

```bash
npm install egl-utils-js
```

Purely additive: nothing in the v0.1.0–v0.3.0 surface changed behaviour, the root entry is
untouched, and there is still no runtime dependency and no new peer.

### It fails fast instead of degrading

This is the first entry that cannot work without a browser, so it had to answer a question the
previous nine never faced. With no DOM present, an export that needs the ambient document
throws `DomContractError` — naming the API, the contract, and the DOM-free alternative — rather
than quietly doing nothing:

```js
import { setVisible } from 'egl-utils-js/dom';
setVisible(el, false); // in Node: DomContractError, code EGL_DOM_CONTRACT
```

The storage wrappers fall back to memory silently, and that was right: a degraded store still
keeps a value. A `setVisible` that quietly does nothing **reports success while the page stays
unchanged**, and is indistinguishable from a hydration bug. Importing the entry is always safe —
the document is resolved per call — so a server render fails on *use*, not on import. An export
handed an explicit element needs no ambient document at all, which keeps these usable inside a
server-side DOM implementation.

### One report instead of a `null` that travels

```js
import { bindElements } from 'egl-utils-js/dom';

const { elements, missing } = bindElements({
  form: '#checkout-form',
  submit: '#checkout-submit',
  total: '[data-total]',
});
if (missing.length > 0) log.warn('markup contract drifted', missing); // e.g. ['total']

bindElements({ app: '#app' }, { strict: true }); // or refuse to boot at all
```

Binding one element at a time turns a selector typo into a `null` that travels and resurfaces
as *"cannot read properties of null"* in a handler, far from its cause. Resolving the whole
contract at once makes the startup check a single assertion.

### One listener, however many rows

```js
import { delegate } from 'egl-utils-js/dom';

const off = delegate(tbody, 'click', 'tr[data-id]', (event, row) => {
  openRecord(row.dataset.id); // `row` is the MATCHED element, not event.target
});
off(); // idempotent; or pass { signal } and let an AbortSignal do it
```

The usual approach — bind each row after each render — costs a listener per row per render and
needs a teardown pass that is easy to forget and invisible when missed. One delegated listener
survives any number of re-renders. The handler gets the **matched** element rather than
`event.target`, which is the deeper node actually clicked (an icon inside a button, a `<span>`
inside a row) — the detail a hand-rolled `closest` call usually forgets, along with the
containment check that stops `closest` climbing past the delegated subtree.

Teardown is an internal `AbortController`, so unsubscribing is one `abort()`: idempotent by
construction, with no retained handler reference and no `removeEventListener` argument list to
keep in sync.

### Setters that stay symmetric

```js
import { setEnabled, setVisible, setValue } from 'egl-utils-js/dom';

setEnabled(elements.submit, form.checkValidity());
setVisible(elements.spinner, isLoading); //  the `hidden` attribute
setVisible(elements.panel, false, { hiddenClass: 'is-hidden' }); // that class INSTEAD

setValue(elements.country, 'IT'); //   select -> selects that option
setValue(elements.subscribed, true); // checkbox -> checked
setValue(elements.name, null); //      clears, rather than writing "null"
```

All three are **no-ops on `null`**, because an absent optional element is a normal state and
requiring `if (el)` at every call site is how those guards get forgotten; a wrong *type* still
throws. `setVisible` drives **one** mechanism, never two — so hide and show always undo each
other, which is not true of the common pair that clears two mechanisms and sets one.
`setValue` dispatches **no** `input`/`change` event: a plain assignment fires none either, and
synthesising one could re-enter the handler that called it.

### The sanitize decision is yours, and it is written down

```js
import { injectFragment } from 'egl-utils-js/dom';
import { sanitizeHtml } from 'egl-utils-js/sanitize';

await injectFragment(host, '/partials/menu.html', { sanitize: sanitizeHtml });
await injectFragment(host, '/dist/shell.html', { sanitize: false }); // trusted, and it SAYS so
```

`sanitize` is **required and has no default**, because both candidates are wrong. Sanitizing by
default would make this entry depend on DOMPurify — an *optional* peer deliberately confined to
`egl-utils-js/sanitize` so consumers who never sanitize pay neither the bytes nor the audit
surface. Not sanitizing by default would make the dangerous choice the quiet one. So the
decision is explicit and greppable: `sanitize: false` is a claim someone made, not an absence
that reads like an oversight.

Errors **propagate** — a non-2xx rejects with `HttpError` carrying status and body — so a shell
assembled from several fragments can be told apart from a partial one. `'beforeend'` and
`'afterbegin'` use `insertAdjacentHTML`, so existing nodes and their listeners survive;
`innerHTML +=` would re-parse and destroy them.

### Two smaller ones

```js
import { autoGrow, withUrlParams } from 'egl-utils-js/dom';

const detach = autoGrow(elements.comment, { maxRows: 8 });

withUrlParams('/api/items?page=1', { page: 2, tag: ['x', 'y'] });
// '/api/items?page=2&tag=x&tag=y'  — one `?`, ever
withUrlParams('/docs#section', { v: buildId }); // '/docs?v=abc#section'
```

`autoGrow` releases the inline height **before** measuring, which is what lets the field shrink
as well as grow, and restores the original styles on detach. `withUrlParams` builds through
`URLSearchParams` over a hand-split URL: the obvious one-liner produces a second `?` the moment
a query string already exists, and the malformed result usually still works against a lenient
server — so that bug ships. It is pure and works on **relative** URLs, which `new URL()` cannot
do without a base.

## Also in this release

- **The platform-API floor gate now covers the DOM.** The project has verified its browser
  support floor against MDN compatibility data since v0.1.0, but the check policed no DOM
  *types* — so using one would have passed silently. Closing that immediately surfaced **eight
  real platform dependencies that had been guarded for months without being declared**, and has
  since caught two more before they could ship undeclared. No behaviour changed; the gate is
  simply now as strict as it always claimed to be.
- The threat model gains an **HTML fragments** boundary with a full STRIDE pass, including the
  explicit statement that the library performs no sanitizing of its own on that path.

## Compatibility

- Node.js ≥ 18; last two Chromium/Firefox/Edge versions; Safari ≥ 15.4.
- ESM and CommonJS, with types generated per format.
- Zero runtime dependencies; no new peer dependency (the sanitizer is a parameter).
- No breaking change: every v0.1.0–v0.3.0 export keeps its behaviour.
