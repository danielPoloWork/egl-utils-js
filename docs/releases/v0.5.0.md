# egl-utils-js v0.5.0

Two **UI components** on `egl-utils-js/dom`: an inline alert and a loading-overlay gate. Both
are instance-based factories that own everything they touch, and neither assumes a design
system — class names, icons, and the overlay's entire presentation are injected, so adopting
a component never means adopting a CSS framework.

```bash
npm install egl-utils-js
```

Purely additive: nothing in the v0.1.0–v0.4.0 surface changed behaviour, the root entry is
untouched, and there is still no runtime dependency and no new peer.

## What's new

| Entry | Added |
|---|---|
| `egl-utils-js/dom` | `inlineAlert`, `loadingOverlay` |

### An alert that cannot steal another alert's timer

```js
import { inlineAlert } from 'egl-utils-js/dom';

const page = inlineAlert(document.querySelector('#page-alert'));
const dialog = inlineAlert(document.querySelector('#dialog-alert'), { autoHideMs: 3_000 });

page.show('danger', 'Could not reach the server.');
dialog.show('success', 'Saved.'); // its own container, its own timer
```

The shape this replaces is the static singleton with an `onInit(containerId)` call. It works
exactly once. The moment a page has two alerts — the usual page-level and dialog-level pair —
the second `onInit` re-points the single static slot, so the dialog's alert inherits the page
alert's pending auto-hide timer and writes into whichever container initialised last. The
failure is silent, intermittent, and reads as *"the message disappeared too early"*.

Here the timer, the close-button listener and the nodes belong to the returned object. A
re-show cancels the pending timer first, so a newer message always gets its full time on
screen instead of inheriting the tail of the older one.

### Markup in a message is shown, not parsed

```js
alerts.show('danger', serverError.message); // textContent — a stray `<` is never an XSS

import { sanitizeHtml } from 'egl-utils-js/sanitize';
alerts.show('info', '<b>3</b> items imported', { html: true, sanitize: sanitizeHtml });
```

`message` is written with `textContent`, so the unescaped-interpolation defect class cannot
occur by accident. Rich content requires the explicit `{ html: true, sanitize }` pair — the
same required decision `injectFragment` takes, so the two HTML-capable surfaces on this entry
are governed by one rule rather than two.

### Adopt a design system with a map, not a fork

```js
const alerts = inlineAlert(host, {
  classes: { base: 'alert', success: 'alert-success', close: 'btn-close' },
  icons: { success: '✓', danger: '⚠' }, // string, Node (cloned per render), or a factory
  closeLabel: 'Chiudi', // the accessible name — a glyph is not a label
});
```

The defaults are inert BEM class names that style nothing until you write CSS, and no icon
set is bundled or named. The close control is `type="button"`, because the default is
`submit` and a close button inside a form would otherwise post it. The alert carries
`role="alert"` for `warning`/`danger` and `role="status"` otherwise: a failure interrupts a
screen reader, a confirmation waits its turn.

### An overlay that counts its owners

```js
import { loadingOverlay } from 'egl-utils-js/dom';

const overlay = loadingOverlay({
  onShow: () => modal.show(),
  onHide: () => modal.hide(),
  minVisibleMs: 400,
  focus: { save: true, root: modalElement },
});

await Promise.all([overlay.wrap(loadA()), overlay.wrap(loadB())]); // shown once, hidden once
```

Three things hand-rolled overlays get wrong, all fixed here:

- **A boolean flag instead of a count.** Two overlapping operations both set
  `isLoading = true`; the first to finish sets it back to `false` and the spinner vanishes
  while the second is still running. `show()` increments a count and returns a release that
  decrements **at most once**, however many times it is called. There is deliberately no
  public `hide()` — a caller can only release their own acquisition, so nobody can close an
  overlay someone else still needs.
- **A floor measured from the wrong instant.** A minimum-visible time added to stop the flash
  usually starts at `show()`; with a modal that fades in over 300 ms, most of the floor is
  spent before anything is on screen and the flash survives the fix. Here the clock starts
  when `onShow` **settles**.
- **A hide that arrives mid-appearance.** It is remembered and honoured once the overlay is
  actually up — a state transition rather than a race, so the gate can never be left up.

With `focus.save` the element focused before the overlay is restored afterwards — but only if
it is still in the document, so an operation that re-rendered its trigger away cannot cause a
throw. Focus inside the overlay is cleared before hiding, which is what avoids the
*"blocked aria-hidden … retained focus"* warning.

A failing `onShow`/`onHide` is **contained**: the gate returns to a consistent state and
nothing is thrown into your code — the rule `logger` applies to a failing sink. A spinner
that cannot render must not fail the save it was decorating, and a stuck overlay — the
failure that would actually harm a user — cannot happen.

Only `focus.save` needs a document, so the gate's timing logic runs under Node too.

## Security

Development dependencies only: js-yaml lifted to `3.15.1` and `4.3.1` on their respective
major lines, clearing two high advisories
([GHSA-5p4m-2wfm-xmqj](https://github.com/advisories/GHSA-5p4m-2wfm-xmqj)) that reached the
tree through `@changesets/cli`. **The published package is unaffected** — it still has zero
runtime dependencies.
