# egl-utils-js v0.6.0

A **composable table pipeline** and the bridge that drives it from the DOM. One owner of the
row set derives one memoized view through a fixed order, so **filtering and sorting compose
instead of discarding each other** — the defect this wave existed to remove. Spec 03 is
complete with this release.

```bash
npm install egl-utils-js
```

Purely additive: nothing in the v0.1.0–v0.5.0 surface changed behaviour, the root entry is
untouched, and there is still no runtime dependency and no new peer.

### Filtering and sorting that compose

```js
import { tablePipeline } from 'egl-utils-js/table';

const table = tablePipeline({
  source: rows,
  pageSize: 25,
  columns: [
    { key: 'name', searchable: true },
    { key: 'score', type: 'number' },
    { key: 'seen', type: 'date' },
  ],
});

table.on('change', (view) => renderRows(view.rows));

table.setFilter('score', '>100'); // filter…
table.toggleSort('name'); //         …then sort the FILTERED set, not the original
```

The shape this replaces keeps a filterer and a sorter side by side, each holding its own copy
of the original rows. Applying one discards the other, so a user who sorts a filtered table
watches their filter disappear. Here there is one owner and one derivation
(`filters → search → sort → paginate`), so neither component needs to know the other exists.

Every command is a transaction that emits **exactly one** `'change'` carrying the derived
view — `setFilter` also returns to page 1, and that is one event, not two. `batch()` collapses
several commands into one. A subscriber therefore never sees a half-applied state, which is
what lets a renderer be a pure function of the view.

### Pure, so it runs on a server

```js
const view = table.view(); // no DOM touched anywhere in this entry
```

`/table` never references `document`. The same pipeline can derive page 1 during
server rendering and hydrate in the browser. `view()` is memoized on a state version, so
reading it twice with no intervening command costs nothing.

The observer surface is **composed, not inherited**: `on`/`once`/`off` delegate to an internal
`EventEmitter` whose `emit` stays private, so nothing outside the pipeline can publish a
`'change'` it did not derive.

### Controls wired without a framework

```js
import { bindTableControls, delegate } from 'egl-utils-js/dom';

const unbind = bindTableControls(table, {
  filters: { status: '#f-status' },
  search: '#q',
  sortHeaders: { root: 'thead', selector: 'th[data-sort-key]' },
  pagination: { prev: '#prev', next: '#next', status: '#page' },
});

// Row rendering stays yours; one delegated listener survives every re-render.
delegate(tbody, 'click', 'tr[data-id]', (event, row) => open(row.dataset.id));

unbind(); // or pass { signal } — either detaches everything
```

The binding speaks **only the pipeline's public API**: it calls commands and listens to
`'change'`. Three details that are easy to get wrong and are handled here:

- **Filter inputs are one-way.** The binding writes the pipeline, never the input, so a
  re-render cannot fight a user mid-keystroke — no cursor jumps.
- **`aria-sort` reflects the derived order**, not the click that was intended, so assistive
  technology reads what the table actually did.
- **Teardown is structural.** The returned unbind — or an aborted `AbortSignal` — detaches
  every listener, cancels every pending debounce, and unsubscribes. No trailing debounce can
  fire into a page that is gone.

The status text comes from an injectable `formatStatus` whose default assumes no language
(`'1 / 4'`), because a default that embeds a human-readable string is policy, not mechanism.

## Fixed

- **The `browser` CI gate is green again** ([BUG-0001](../bugs/2026/08/BUG-0001-webkit-row-click-intercepted.md)).
  A Playwright case aimed its click at a `<tr>`, which made it depend on a hit-test the
  standard does not pin down: the CI WebKit build resolved the row's centre to the ancestor
  `<table>`, which Playwright refuses to click through. No library behaviour was affected —
  delegation worked in every engine throughout — but the gate had been red since the previous
  milestone, and a red gate hides the next real regression.

## Notes

- **NFR-13 now has the measurement its clause specifies.** The budget reads "≤ 50 ms *on the
  CI runner*"; until this release only workstation figures existed, because the benchmark gate
  was discarding the measurement (see below). On the runner: **10.24 ms mean, 11.96 ms p99**
  for a full derivation over 10,000 rows with 3 filters and a 2-key sort — 4.9x headroom.
- **The benchmark gate was collecting less than it appeared to.** Its classifier discarded any
  group it could not pair with a baseline library, so all ten absolute benchmarks ran in CI
  and were thrown away — the recorded baseline held 13 entries where it should have held 23.
  Classification is now total: anything unclassifiable **fails** the run rather than silently
  leaving the gate. No library code changed.
- That fix also corrected two assumptions this project had written down: a hosted CI runner is
  not slower than the development workstation, nor noisier — it is **~2x faster and an order
  of magnitude more stable**. The corrections landed in the ADR, the spec, and the benchmark
  report rather than being quietly dropped.
- Sizes: `/table` **3273 B**, `/dom` **4718 B**, both within their (amended) clauses;
  `{tablePipeline}` **3250 B** and `{bindTableControls}` **2093 B** when imported alone.
- **1290 tests at 100% line and branch coverage**, and the browser suite now exercises
  `/table` and `/dom` in Chromium, Firefox and WebKit: **90/90** green.
- Milestones 1–13 are complete. Next is the opt-in `egl-utils-js/bootstrap` toolkit, built on
  these entries rather than replacing them.
