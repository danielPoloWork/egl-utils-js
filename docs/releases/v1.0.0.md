# egl-utils-js v1.0.0

**The first release whose version means what SemVer says it means.**

```bash
npm install egl-utils-js
```

No new capability ships here. Specs 01–04 were delivered at v0.9.0, and M17 added three more root exports on the way here —
**113 exports across ten entries, 102 distinct names** — so the question a 1.0 answers is not "is it ready" but **"what are we committing never
to change again."** Milestone 17 spent its entire budget on that question, and nothing else.

That is why **1.0 arrives after seven breaking changes rather than before them.** A readiness
review read the whole public surface looking for what the freeze would make permanent, filed what
it found, and the twelve items that followed fixed each one while it was still cheap. Every rename
below would have cost a major tomorrow.

## The stability promise

**MAJOR-protected from today.** Anything in this list changes only in a 2.0:

- **Every named export** — all 113, across the root and the nine subpath entries.
- **Every `EGL_*` error code**, and the `.code`-not-`instanceof` identity contract that goes with
  them.
- **Every `exports`-map path**, so a deep import that resolves today keeps resolving.
- **The supported-runtime floor.** Raising it is breaking, which is exactly why it moved to Node 22
  and Safari 16.4 *before* this release.

**Minor:** new exports, new options, new error classes and codes. **Patch:** fixes that do not
change a documented contract.

**Deliberately outside the promise**, so it is relied on knowingly rather than discovered:

- **Byte budgets.** The size figures are a quality gate, not an API; they move with measurement.
- **Generated `.d.ts` internals.** The public *types* are stable; the shape TypeDoc or tsup emit
  for an internal `@typedef` is not.
- **Error message text.** Branch on `.code`, never on wording.
- **Peer *behaviour*.** We pin a compatible range; what Bootstrap or DOMPurify do inside it is
  theirs. Keeping the peer patched is the consumer's job, and
  [`SECURITY.md`](../../SECURITY.md) says so where it is read.

The maintenance protocol — how a fix flows, deprecation policy, security response — is
[`docs/workflow/maintenance.md`](../workflow/maintenance.md).

## Upgrading from 0.9.x

Seven breaking changes, each with a one-line fix. The full detail is in
[the changelog](../changelog/v1/v1.0.0.md).

| What changed | What to do |
|---|---|
| **Node 18/20 dropped** | Move to Node >= 22 (Safari floor is now 16.4) |
| **Unknown option keys throw** | Fix the typo the `TypeError` names — it was being silently ignored |
| **Unknown keys in columns/items/labels throw** | Same, one level deeper; row *data* is never checked |
| **`label` is what the user sees; `ariaLabel` is the accessible name** | Rename `label` → `ariaLabel` on `bsIcon`, `bsButtonGroup`, `bsCloseButton`, `bsSpinner`, `bsProgress`, `bsBreadcrumb` |
| **`bsToast` auto-dismiss is one option** | `{autohide, delay}` → `{autoHideMs}` (or `false`) |
| **Commands throw, queries answer** | `loadingOverlay.show()` → `acquire()`; `bsToast.show()` → `add()`; `onPage` → `onPageChange`; `setData`/`setValue`/`setView` where new state is passed |
| **`/sanitize` looks DOMPurify up** | `sanitizeHtml(html, { dompurify: DOMPurify })`, or expose `window.DOMPurify` |

Two of those are worth a second look because they change *when* you find out about a mistake, not
just what to type: unknown-key strictness turns silently-ignored config into a loud failure, and
the sanitizer's peer moves from a build-time import to a lookup that fails at the first call with
`EGL_PEER_MISSING`. Neither ever degrades quietly — that was the point.

## Also in this release

- **The API reference is published** per release at
  <https://danielpolowork.github.io/egl-utils-js/>, generated from the JSDoc types.
- **Two of four builds are gone** from the tarball: the `#webcrypto` conditional shim collapsed
  once the Node 22 floor made `globalThis.crypto` universal, taking the `dist/node` pair and the
  exports map's `node` condition with it. Public API unchanged.
- **`/sanitize` loads on a plain HTML page** with no bundler and no import map — the tenth of ten
  entries to do so.
