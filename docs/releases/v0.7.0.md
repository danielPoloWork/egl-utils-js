# egl-utils-js v0.7.0

A new opt-in entry, **`egl-utils-js/bootstrap`**: thirteen builders that produce Bootstrap 5
markup as **real DOM nodes**, never HTML strings. That is the whole point of the design —
the prevailing way to render Bootstrap from data is a template literal assigned to
`innerHTML`, which is an injection every time a field turns out to be attacker-influenced.
Here there is no markup string for data to break out of.

```bash
npm install egl-utils-js
```

Purely additive: nothing in the v0.1.0–v0.6.0 surface changed behaviour, the root entry is
untouched, and the package still declares **zero runtime dependencies**. `bootstrap` is an
*optional* peer — nothing in this release requires it, and every builder here works with
none installed. You supply Bootstrap's CSS and any icon font; the toolkit emits markup and
class names only.

## What's new

| Entry | Added |
|---|---|
| `egl-utils-js/bootstrap` *(new)* | `bsIcon`, `bootstrapIconsSet`, `materialIconsSet`, `bsBadge`, `bsButton`, `bsButtonGroup`, `bsCloseButton`, `bsSpinner`, `bsProgress`, `bsPlaceholder`, `bsCard`, `bsListGroup`, `bsBreadcrumb`, `bsAlert`, `bsPagination` |

### Escaping you cannot forget

```js
import { bsBadge, bsCard, bsButton } from 'egl-utils-js/bootstrap';

// Text is escaped on the way in — a record field containing markup is displayed, not parsed.
container.append(bsBadge(record.status, { variant: 'danger', pill: true }));

// Slots take a string, a node, or an array of either:
bsCard({
  image: { src: '/cover.jpg', alt: '' },   // alt is required; '' declares it decorative
  title: order.customer,
  text: [order.summary, bsBadge(order.status, { variant: 'success' })],
  actions: bsButton({ label: 'Open', size: 'sm' }),
});
```

Markup is still available, but only as a decision you make in code — the same
`{ html: true, sanitize }` pair `injectFragment` and `inlineAlert` already use, with no
default sanitizer:

```js
import { sanitizeHtml } from 'egl-utils-js/sanitize';

bsBadge('<b>3</b> new', { html: true, sanitize: sanitizeHtml });
bsBadge(trustedMarkup, { html: true, sanitize: false }); // a signed decision, not a silence
```

The promise is verified by attack rather than by review: every documented sanitizer-bypass
payload in the project's corpus is pushed through **every content-accepting option of every
builder**, in jsdom and in real engines, including a re-parse of `outerHTML` that closes the
mXSS class those payloads come from.

### An unnamed control is refused, not warned about

```js
bsButton({ icon: 'trash', label: 'Delete row', labelHidden: true }); // ✅ named, icon-only
bsButton({ icon: 'trash' });                                        // ❌ TypeError
```

An icon-only control with no accessible name is announced as just "button", and is
indistinguishable from every other unnamed button on the page. Since the fix is one option,
the builder refuses to produce the broken thing — a console warning would ship it.

### Composition, not reimplementation

Two of the composites are the framework-agnostic components wearing Bootstrap's clothes, so
a fix to either engine reaches both entries and the two cannot drift:

```js
// bsAlert IS inlineAlert (v0.5.0) — same instance API, same per-instance timers.
const alerts = bsAlert(document.querySelector('#form-alert'));
alerts.show('success', 'Saved.', { autoHideMs: 3_000 });

// bsPagination speaks the shape tablePipeline.view() already returns (v0.6.0) — no adapter.
const pager = bsPagination(footer, { onPage: (n) => table.setPage(n) });
table.on('change', (view) => pager.update(view));
```

`bsListGroup` follows the same rule for interaction: one delegated listener is attached once
and survives every `update()`, so re-rendering a data-driven list rebinds nothing and leaks
nothing.

### Everything is injected

Icon sets are pure data — two presets ship (Bootstrap Icons, Material), and any other
convention is a `{ render }` function away. Class maps, human-readable strings and the
document are options too, which is what lets a builder run inside an iframe or a
server-side DOM:

```js
import { bsIcon, materialIconsSet } from 'egl-utils-js/bootstrap';

bsIcon('gear');                                // <i class="bi bi-gear" aria-hidden="true">
bsIcon('delete', { set: materialIconsSet });   // <span class="material-icons">delete</span>
```

## Fixed

- **`inlineAlert`** (`egl-utils-js/dom`, v0.5.0): an empty close icon no longer hides the
  close control. A design system that draws its close glyph in CSS — Bootstrap's
  `.btn-close`, for one — supplies an empty icon, which previously left a dismissible alert
  nobody could dismiss. `dismissible: false` remains the way to ask for no close button.
- **Smaller bundles across the board.** The entry's frozen constant maps are annotated
  `/* @__PURE__ */`, so a bundler drops the ones an importer does not use. Importing a
  single icon preset fell from 358 B to **43 B**.
- **Build:** the lockfile is back in step with `package.json`, and the `nanoid` advisory
  reached through `tsup > postcss` is lifted inside its own major line. Neither affected
  shipped code (BUG-0002).

## Compatibility

- **Node.js** ≥ 18, evergreen browsers, **Safari ≥ 15.4** — unchanged.
- **Zero runtime dependencies** — unchanged. `bootstrap` (`^5`) joins `dompurify` as an
  **optional** peer; neither is required, and nothing in this release touches either.
- Every existing export keeps its behaviour, its types and its size budget. Adopting the
  new entry is opt-in, per import.
