# v1.1.0 — 2026-08-21

**The plain HTML page becomes a first-class consumer.**

Every wave until now shipped for the npm consumer: install, import, let a bundler resolve the
graph. This one closes the gap for the page that has no `package.json`, no bundler and no Node —
an intranet tool, a server-rendered app with a `<script>` tag, a reproduction on CodePen. The
library now works by being **loaded**, not by being **built**.

Nothing existing changes. Additive throughout: the `exports` map is byte-for-byte identical, a
bundler consumer re-bundles to the same graph, and `sideEffects: false` and the zero runtime
dependencies are untouched. Milestone 18 delivered spec 05 (F82–F87) in five items; four ADRs
record its decisions: [0058](../../adr/0058-the-per-function-budget-keeps-its-exceptions-named.md)'s
successors [0059](../../adr/0059-one-file-one-global-and-a-budget-repinned.md),
[0060](../../adr/0060-the-cdn-default-and-what-the-tarball-proves.md) and
[0061](../../adr/0061-served-bytes-are-their-own-accounting.md).

## Added

- **A global single-file artifact** — `dist/global/egl-utils.global.js`, a minified IIFE with a
  sourcemap, loadable by a classic `<script src>` with no `type="module"`
  ([ADR-0059](../../adr/0059-one-file-one-global-and-a-budget-repinned.md), roadmap 18.2, spec 05
  F83). It reads as the single global `egl`: the root entry's exports at the top level
  (`egl.retry`, `egl.VERSION`), each subpath as a sub-namespace named after its `exports` path
  (`egl.text`, `egl.table`, `egl.bootstrap`, …). Nothing is renamed.

  ```html
  <script src="https://cdn.jsdelivr.net/npm/egl-utils-js@1.1.0"></script>
  <script>
    const rows = egl.table.paginate(data, { page: 1, pageSize: 20 });
    document.body.append(egl.bootstrap.bsBadge(`${rows.total} results`));
  </script>
  ```

  The namespace is composed by `export *` rather than by a hand-written object, so it cannot
  drift by omission when an entry gains an export. Loading the file has **no side effect beyond
  defining `egl`** — measured, not asserted: a packaging gate diffs the page's own globals across
  the load, and the browser suite does the same in three engines.

- **A CDN default** — the `unpkg` and `jsdelivr` fields name that artifact, so the bare package
  URL serves something a `<script src>` can run
  ([ADR-0060](../../adr/0060-the-cdn-default-and-what-the-tarball-proves.md), roadmap 18.3, spec
  05 F84). Both fields carry the same value, so the URL means the same thing on either service.
  The deep `dist/esm/<entry>.js` paths remain the module-consumer route, unchanged.

- **Documentation for both routes** — a README section, *"Use from a browser, without npm"*, with
  copy-pasteable version-pinned URLs: the deep-ESM route per entry, the artifact route, how each
  optional peer is supplied on either, and the cross-version rule (roadmap 18.4, spec 05 F85).
  **Pin one version for every `egl-utils-js` URL on a page**: entries share content-hashed chunks
  *within* a version, not across one, so mixing versions double-loads shared code.

- **Measured route costs**, gated in CI so the figures cannot drift into fiction
  ([ADR-0061](../../adr/0061-served-bytes-are-their-own-accounting.md), roadmap 18.5, spec 05
  F87). What a browser actually transfers, per route — every file in the entry's chunk graph,
  each compressed as its own response:

  | Route | Requests | Transferred |
  |---|---:|---:|
  | `/errors` | 2 | 1.07 kB |
  | `/net` | 2 | 1.34 kB |
  | `/text` | 3 | 1.67 kB |
  | `/sanitize` | 3 | 2.91 kB |
  | `/logging` | 3 | 3.06 kB |
  | `/storage` | 4 | 4.25 kB |
  | `/table` | 4 | 6.75 kB |
  | `/dom` | 7 | 10.85 kB |
  | root | 7 | 13.45 kB |
  | `/bootstrap` | 7 | 31.28 kB |
  | the artifact | **1** | 31.51 kB |

  Read off it: **if you need `/bootstrap`, take the artifact** — the whole surface in one request
  for within 1% of what that one entry costs in seven. These figures are larger than the
  per-function budgets quoted elsewhere, and that is not a contradiction: those measure what a
  *bundler* ships after tree-shaking, while a static page downloads whole files. Both are real;
  they belong to different consumers.

## Verified

- **The no-bundler routes are proved in CI, on three engines** (Chromium, Firefox, WebKit),
  loading the package *exactly as the README says to* — deep ESM with no import map, and the
  artifact through a classic `<script src>` (roadmap 18.5, spec 05 F86). Per route: the entry is
  reachable, `VERSION` matches `package.json`, a builder renders and escapes, a peer-backed call
  works once its peer arrives from a script tag, and peer absence surfaces as `EGL_PEER_MISSING`
  **at the call** rather than as a load failure.

- **`/sanitize` on a page that never had DOMPurify** (roadmap 18.1, spec 05 F82). The v1.0.0 work
  made the peer a value looked up rather than a bare `import`; this release proves the
  consequence on a fixture where the peer was never present — because peer absence is the
  security-relevant half, and the wrong answer to it is returning the caller's markup
  unsanitized.

- **Three new packaging gates** run in `check:package`: the artifact's surface, version lockstep
  and single-global guarantee against the built file; every advertised path — CDN fields, all 41
  `exports` targets, the artifact's sourcemap — present in the **packed tarball**; and the served
  bytes above. Each was provoked in every direction to confirm it can actually fail.

## Notes

- **`main`, `module` and `browser` are still absent, deliberately**, and a gate now asserts it.
  They are the pre-`exports` resolution fields, and bundlers still honour them; `browser` in
  particular would silently redirect bundler consumers onto the single-file artifact. The
  `exports` map stays the only resolution surface.
- **No new platform APIs** — the deny-by-default api-floor inventory is unchanged, and the
  browserslist floor does not move (spec 05 NFR-24).
- The optional peers stay **external** on both routes and are resolved at first use. A page that
  already loads Bootstrap's or DOMPurify's own bundle needs no configuration; nothing is bundled
  into the artifact, so no page ends up with two copies of a peer it already has.
