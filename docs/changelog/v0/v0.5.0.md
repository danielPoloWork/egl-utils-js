# v0.5.0 — 2026-08-07

Milestone 12: the two **UI components** on `egl-utils-js/dom` — `inlineAlert` and
`loadingOverlay`. Both are instance-based factories that own everything they touch, and
neither assumes a design system: class names, icons, and the entire presentation of the
overlay are injected, so adopting a component never means adopting a CSS framework.

The contract is [`docs/specs/03_spec_dom_ui_table.md`](../../specs/03_spec_dom_ui_table.md)
(F49–F50 land here; F42 and F51 — the table pipeline and its DOM binding — complete spec 03
in M13). Two ADRs record the decisions:
[ADR-0031](../../adr/0031-component-instances-and-the-alert-budget.md) and
[ADR-0032](../../adr/0032-overlay-gate-refcount-floor-and-focus.md).

Purely additive: nothing in the v0.1.0–v0.4.0 surface changed behaviour, the root entry is
untouched, and there is still no runtime dependency and no new peer.

### Added

- **`inlineAlert(container, options)`** on `egl-utils-js/dom` (ROADMAP 12.1, spec 03 F49) —
  a dismissible alert banner bound to one container, returning `{show, hide, destroy}`.

  **Every instance owns its state.** The shape this replaces is the static singleton with an
  `onInit(containerId)` call, which works exactly once: the moment a page has two alerts —
  the usual page-level and dialog-level pair — the second `onInit` re-points the single
  static slot, so the dialog's alert inherits the page alert's pending auto-hide timer and
  writes into whichever container initialised last. The failure is silent, intermittent, and
  reads as *"the message disappeared too early"*. Here the timer, the close-button listener
  and the nodes belong to the returned object, and a re-show cancels the pending timer first,
  so the newer message always gets its full time on screen.

  **Policy is injected; only mechanism ships.** `classes` and `icons` are maps merged over
  neutral, framework-free BEM defaults (`egl-alert`, `egl-alert--success`, …) that style
  nothing until a consumer writes CSS. No icon set is bundled or named; an icon may be a
  string, a node (**cloned** per render, so one map serves many instances), or a factory. A
  Bootstrap look is one `classes` map away, and the library never learns Bootstrap exists.

  **Text by default, markup by decision.** `message` is written with `textContent`, so a
  value containing `<` is displayed rather than parsed — the unescaped-interpolation defect
  class simply cannot occur by accident. Rich content requires the explicit
  `{ html: true, sanitize }` pair, byte-for-byte the `injectFragment` contract from
  [ADR-0030](../../adr/0030-sanitize-is-a-required-parameter.md), so the entry's two
  HTML-capable surfaces are governed by one rule rather than two.

  Details that are easy to get wrong and are covered here: the close control is
  `type="button"` (the default is `submit`, so a close button inside a form would post it),
  its accessible name is configurable because a glyph is not a label, and the alert carries
  `role="alert"` for `warning`/`danger` and `role="status"` otherwise — a failure interrupts
  a screen reader, a confirmation waits its turn. Nodes are built in the **container's own
  document** on first `show()`, so an alert works inside an iframe or a server-side DOM
  implementation and an unused instance leaves the container untouched.

- **`loadingOverlay(options)`** on `egl-utils-js/dom` (ROADMAP 12.2, spec 03 F50) — a
  reference-counted visibility gate over an injected `onShow`/`onHide` pair, returning
  `{show, wrap, isShown, destroy}`.

  The gate owns *when* an overlay is visible; the hooks own *what* is visible. That split is
  the whole design: one gate drives a modal, a spinner, or a progress bar. It fixes the three
  things hand-rolled overlays get wrong, each of which is usually shipped:

  - **A boolean flag instead of a count.** Two overlapping operations both set
    `isLoading = true`; the first to finish sets it back to `false` and the overlay vanishes
    while the second is still running. `show()` increments a count and returns a release that
    decrements **at most once**, however many times it is called — idempotence is not
    politeness here, since a double release would drop a count another owner still holds.
    There is deliberately no public `hide()`: a caller can only release their own
    acquisition, so no caller can close an overlay someone else still needs.
  - **A floor measured from the wrong instant.** A minimum-visible time added to stop the
    flash usually starts at `show()`; with an animated presentation most of it is spent
    before anything is on screen, so the flash survives the fix. Here the clock starts when
    `onShow` **settles**.
  - **A hide that arrives mid-appearance.** It is remembered and honoured once the overlay is
    actually up and the floor has elapsed — a state transition rather than a race, so the
    gate can never be left up.

  With `focus.save` the active element is captured before showing, focus inside the overlay
  is cleared before hiding — which is what avoids the *"blocked aria-hidden … retained
  focus"* warning — and the original element is refocused afterwards **only if it is still in
  the document**, so an operation that re-rendered its trigger away cannot cause a throw.
  `wrap(promiseOrFn)` releases on success, rejection, and synchronous throw alike.

  **Presentation failures are contained.** A throwing or rejecting hook leaves the gate in a
  consistent state and is never thrown into the caller — the rule
  [ADR-0027](../../adr/0027-logging-formatter-sink-split.md) applies to a failing log sink,
  applied to a second cross-cutting concern: a spinner that cannot render must not fail the
  save it was decorating. The alternative failure — a stuck overlay — is the one that would
  actually harm a user, and it cannot happen.

### Changed

- Spec 03's **F49 and F50 option lists were amended** as each was implemented, to the
  contract NFR-15 already implied: both gained a `signal`, and F50 gained `destroy()`, since
  NFR-15 had always named them among the exports whose teardown must ride an aborted signal.
  The option lists were the incomplete half, not the requirement.
- Spec 03's **NFR-12 budget clause for `inlineAlert` moved from an indicative 1.25 kB to
  1.5 kB** ([ADR-0031](../../adr/0031-component-instances-and-the-alert-budget.md)). The
  figure was written before the contract existed and did not account for the sanitize
  decision, the `ownerDocument` path, the `AbortSignal` teardown, or the ARIA role mapping. A
  trimming pass recovered 29 B; going further meant deleting capabilities the contract asks
  for. The entry-level promise that governs consumers — `/dom` ≤ 4 kB — was neither spent nor
  renegotiated.

### Security

- **Development dependencies only:** js-yaml lifted to `3.15.1` and `4.3.1` on their
  respective major lines, clearing two high advisories
  ([GHSA-5p4m-2wfm-xmqj](https://github.com/advisories/GHSA-5p4m-2wfm-xmqj)) that reached the
  tree through `@changesets/cli`
  ([ADR-0033](../../adr/0033-js-yaml-overrides-stay-inside-their-major-line.md)). The
  published package is unaffected: it still has zero runtime dependencies.

  The fix carries a rule worth repeating. A range-scoped override key limits *which*
  dependency instance is lifted, not *how far*: an open replacement range (`">=3.15.1"`)
  installed `js-yaml@5.2.3` onto a 3.x consumer — a two-major jump that the install performs
  silently. **Scope the key and pin the replacement.**
